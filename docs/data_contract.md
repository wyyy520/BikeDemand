# 数据处理规范

## 1. 本项目使用的数据集

数据来源为深圳市政府数据开放平台的“共享单车企业每日订单表”接口，数据覆盖 2021 年部分月份，原始记录规模很大。报告中应注明：数据来源为“深圳市政府数据开放平台”。平台条款也要求基于其数据产生的成果标注数据来源。[数据接口详情页](https://opendata.sz.gov.cn/data/api/toApiDetails/29200_00403627)

该数据没有稳定的站点编号，而是提供起终点经纬度。因此本项目将“站点需求预测”调整为“空间网格需求预测”，并分别统计每个网格的借车量和还车量。

## 2. 原始订单字段

实际字段不同的时候，在预处理脚本中建立别名映射，不直接修改原始文件。

| 逻辑字段 | 推荐字段名 | 说明 |
|---|---|---|
| 借车时间 | `start_time` | 订单开始时间 |
| 还车时间 | `end_time` | 订单结束时间 |
| 用户 | `user_id` | 脱敏用户标识，可不用于建模 |
| 企业 | `company_id` | 企业标识，可用于分组统计 |
| 借车纬度/经度 | `start_lat`/`start_lon` | BD09 坐标 |
| 还车纬度/经度 | `end_lat`/`end_lon` | BD09 坐标 |

如果接口返回的实际字段名不同，在预处理脚本中建立别名映射，不直接修改原始文件。

## 3. 清洗规则

1. 时间字段解析为统一时区的 `datetime`；
2. 删除借车时间、还车时间或起终点坐标缺失的记录；
3. 删除 `end_time < start_time` 的异常订单；
4. 删除重复订单；
5. 检查极端骑行时长并记录删除阈值；
6. 原始订单不覆盖，清洗结果写入 `data/processed/`。

## 4. 空间区域构造

第一版使用规则网格，不把每一个经纬度点当作独立站点：

1. 在 BD09 坐标系下将深圳划分为 500 米左右的网格；
2. 统计每个网格的订单量，删除极低频网格；
3. 只根据训练集需求量选择前 30～50 个活跃网格用于 Transformer；
4. EDA 可以展示全部活跃网格，模型使用前 30～50 个网格控制输出维度。

若 500 米网格过于稀疏，则改用约 1 公里网格。网格编号应由经纬度经过固定原点和网格大小计算得到，保证训练、验证、测试使用同一空间划分。

## 5. 聚合规则

使用 30 分钟时间桶：

```text
out_count = groupby(floor(start_time, 30min), start_grid).size()
in_count  = groupby(floor(end_time, 30min), end_grid).size()
```

建立完整的“时间 × 网格”索引，缺少订单的组合补为 0。只使用训练集确定保留网格列表，避免测试集信息影响区域选择。

## 6. 数据规模和下载策略

2.4 亿条原始订单不适合直接一次性读入内存，也不建议随机抽取订单。优先使用连续日期范围，并按日期分块处理：

- 调试：连续 7 天；
- 正式作业：连续 2～3 个月；
- 资源充足：使用全部可获得月份，按月份分块聚合后再合并。

如果接口支持日期过滤，应使用日期过滤和分页；如果只支持分页，优先申请平台的批量文件或按日保存分页结果。每次读取后立即聚合成“日期 × 30 分钟 × 网格”的小表，不保存全部订单到内存。

## 7. 防止数据泄露

- 时间切分前不能使用全量数据计算标准化参数；
- 站点筛选、均值填补和滚动统计原则上只使用训练历史；
- 预测时只能使用预测时刻之前的数据；
- 测试集只用于最终评价，不能用于调参。

## 8. 处理后文件

建议输出 `data/processed/demand_30min.parquet`，字段至少包含：

```text
timestamp, grid_id, out_count, in_count, center_lat, center_lon
```
